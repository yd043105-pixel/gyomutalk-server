# 교무톡 제품별 저장소 관리

## 제품과 저장소

| 저장소 | 배포 대상 | 포함 범위 |
| --- | --- | --- |
| gyomutalk-server | 학교 Windows 서버 관리자 | 교내 업무 서버, 학교 소식 서버, 관리자 UI, 운영 도구 |
| gyomutalk-windows | Windows 교직원 | 사용자 메신저와 Windows 설치 마법사 |
| gyomutalk-mac | Mac 교직원 | 네이티브 Mac 앱, Apple Silicon·Intel 시험 빌드 |

기존 yymessenger는 모바일 앱과 기존 이력을 유지한다. 교사용 앱 이름은 교무톡, 학생·학부모용은 학교톡이다. 모바일 앱 전용 저장소는 이번에 추가하지 않는다.

## 학교별 운영

각 학교는 자체 서버와 데이터를 관리한다. 학교 검색용 목록은 승인된 학교명·지역·학교 ID·역할별 HTTPS 주소를 안내한다. 계정·메시지·첨부를 개발자 공통 서버에 모아두는 구조로 바꾸지 않는다. 교직원 서버와 학교 소식 서버의 권한과 역할 분리를 유지한다.

학교는 도입·운영 내부결재 승인 문서와 필요한 심의·보안·개인정보 검토 자료를 학교 문서함에 보관한다. 개발자의 검색 목록 등록 승인은 학교 내부 승인·법적 요건 충족·보안 인증을 의미하지 않는다. 원본 결재 문서나 학교 보안 자료는 공개 저장소나 등록 신청 메일에 첨부하지 않는다. 작성용 양식은 docs/public에 있다.

## 공통 코드와 호환성

서버와 클라이언트가 동일한 계약·학교 검색·보안 코드를 사용하도록 필요한 공통 소스 사본을 각 저장소에 포함한다. 공통 코드만을 위한 네 번째 저장소나 비공개 의존성은 만들지 않는다. 각 저장소의 source-snapshot.json은 분리 시점 원본 커밋과 공유 소스 해시를 기록한다.

분리 후 기능 수정은 해당 제품 저장소에서 진행한다. API·DTO·학교 검색 형식·세션 규칙을 수정할 때는 호환 대상을 함께 점검하고 필요한 공통 코드 변경만 다른 저장소와 모바일 원본에 반영한다. 파일을 자동으로 덮어쓰는 동기화는 하지 않는다. 호환 정보의 기준 파일은 protocol-baseline.json이며 제품 버전과 프로토콜 변경을 구분한다.

관리자 UI와 Windows 사용자 UI는 현재 같은 WPF 프로젝트에서 시작한다. 서버 저장소에는 서버·관리자를 빌드하는 데 필요한 UI 원본을 포함하지만 서버 설치본만 배포한다. Windows 저장소에는 서버 실행 파일·서버 소스가 없으며 사용자 설치본만 배포한다. 메뉴 권한과 서버 검증은 유지한다.

Mac 저장소의 SchoolMessenger.Mobile 폴더는 Mac이 사용하는 공통 화면 소스 사본이다. Android·iOS 앱 프로젝트나 배포 기능을 옮기는 것이 아니다. Mac 실제 실행 검사는 고정된 서버 저장소 커밋을 시험용으로 체크아웃하여 수행하며 운영 서버에 연결하지 않는다.

## 버전과 배포

초기 버전은 모두 1.0.0으로 유지한다. 새 저장소에는 제품별 검증·시험 산출물 생성 워크플로만 설정한다. 이번 작업에서 정식 릴리즈·자동 공개 배포·자동 업데이트를 활성화하지 않는다. 설치 ID·앱 ID·데이터 경로를 유지하여 이름 변경과 저장소 분리만으로 기존 계정을 잃지 않게 한다.

각 제품의 GitHub Actions 결과가 성공한 뒤 산출물을 내려받아 시험한다. 정식 출시 시 제품별 Release와 서명·공증·업데이트 정책을 확정한다. 저장소 분리 자체가 설치된 프로그램을 자동 업데이트하지는 않는다.
