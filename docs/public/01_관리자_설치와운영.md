# 관리자 설치와 운영
## 1. 설치 전에 준비하세요
> 처음에는 같은 PC 안에서만 시험하세요. 운영 서버에 이미 자료가 있다면 새로 초기화하지 말고 6장의 업데이트 절차부터 확인하세요.
### 관리자 준비표
| 준비할 것 | 확인 방법 |
| 서버용 Windows PC | Windows 10 2004 이상 또는 Windows 11의 64비트 환경, 실제 사양·디스크 여유 확인 |
| Windows 설치 권한 | 학교에서 허용한 설치 관리자 권한 준비 |
| 앱 관리자 계정 | 최초 서버 시작 시 admin 계정의 개인 비밀번호 지정 |
| 시험 자료 | 실제 학생 정보가 없는 교직원·학생·학부모 가상 계정과 파일 |
| 운영 전 담당자 | 계정 관리, 네트워크, 백업, 장애 대응 담당자와 학교 문의처 지정 |
### 두 서버의 역할을 구분하세요
교내 업무 서버는 교직원 메시지와 내부 업무를 담당합니다. 학교 소식 서버는 학생·학부모 앱의 공지·시간표·상담 등 허용된 서비스를 담당합니다. 교직원의 개인 업무 메시지를 학교 소식 서버에 복제하는 구조가 아닙니다.
두 역할을 한 PC에 설치하여 기능을 시험할 수 있습니다. 다만 폴더만 나누는 것으로 보안이 격리되지는 않습니다. 실제 외부 접속 운영은 학교 담당자가 가상 컴퓨터·운영 계정·네트워크 등의 분리 방식을 검토한 뒤 진행하세요.
### 내부결재 승인 문서를 남기세요
학교가 자체 서버를 운영하므로 도입·운영 전에 내부결재를 받고 문서번호·결재일·승인된 기능과 운영 범위를 학교에 보관하세요. 03_관리자_준비양식의 ‘학교도입_내부기안_작성양식.txt’를 학교 서식으로 옮겨 작성할 수 있습니다. 원본과 심의·검토 자료는 보호된 학교 문서함에 보관하고 개발자 신청 메일이나 공개 GitHub에 올리지 않습니다.
교육현장에는 학교장 책임의 자체 구축·민간 클라우드 이용과 해당 사업의 보안성 검토 절차 생략 규정이 있습니다. 해당하면 일반기관 제출서류를 일괄 요구하지 않고 학교장 승인·적용 범위 판단·자체 보안대책을 기록합니다. 개인정보 처리 요건과 학습지원 소프트웨어 선정 시 학운위 심의는 별도로 확인하세요. 자세한 구분은 준비양식의 ‘교육현장_운영고지.txt’를 읽으세요.
## 2. 설치하고 첫 서버를 켜세요
### 설치 마법사
1. 02_설치파일 / 01_서버관리자_Windows에서 교무톡_서버설치_1.0.0_Windows.exe를 실행합니다. 출처와 파일을 학교 담당자가 확인한 뒤 설치합니다.
2. 서버 역할을 선택합니다. 일반적인 내부 시험은 ‘교내 업무 서버 PC’를 선택합니다. 두 역할을 함께 시험하려면 ‘사용자 지정 · 시험 환경’에서 교내 업무 서버·학교 소식 서버·관리자 프로그램을 선택합니다.
3. 바탕화면 바로가기와 ‘Windows 로그인 시 관리자 프로그램 자동 실행’을 원하는 대로 체크합니다.
4. 설치를 끝내고 ‘관리자 프로그램 실행’을 선택합니다. 나중에는 시작 메뉴의 ‘교무톡 관리자 및 서버 → 관리자 프로그램’을 엽니다.
### 최초 실행 · 간편 설정 (추천)
관리자 프로그램은 교내 업무 서버를 처음부터 ‘학교 운영 · 간편 설정 (추천)’으로 엽니다. 운영 설정 파일을 따로 만들 필요가 없습니다.
1. **학교 이름**을 입력합니다. 교사 메신저의 학교 검색과 화면 제목에 표시됩니다.
2. **관리자 아이디**(영문·숫자·._- 3~32자)와 **최초 관리자 비밀번호**(12~128자)를 정하고 비밀번호를 한 번 더 입력합니다. 아이디는 처음 만들 때만 정할 수 있습니다. 비밀번호를 설명서나 공유 폴더에 적지 마세요.
3. **학교장 승인(내부결재) 문서**의 ‘문서 선택’을 눌러 결재 파일(PDF·HWP 등)을 고릅니다. 파일은 이 PC에만 보관하고 지문(해시)으로 학교 검토 기록을 만듭니다. 1년마다 새 승인 문서로 갱신합니다.
4. ‘서버 시작’을 누릅니다. 처음 시작할 때 Windows 방화벽 창이 뜨면 ‘개인 네트워크’에 허용합니다.
5. 상태가 ‘실행 중’이 되면 **교사 PC 접속 주소**(예: https://192.168.0.10:18443)와 **연결 확인 코드**(예: CB3D-58BE-D3A2-B39F)가 표시됩니다. 이 두 가지를 교직원에게 안내합니다.
> 정상 완료: ‘관리자 로그인’에서 방금 정한 아이디와 비밀번호로 로그인되고 교직원·권한 등의 관리 메뉴가 열립니다. HTTPS 인증서·접속 허용 대역·교사 PC 자동검색은 프로그램이 자동으로 설정합니다.

‘운영 점검’ 목록에는 백업 위치(다른 드라이브 권장), UPS, 알림 메일처럼 가동 후 챙길 일이 표시됩니다. 서버 가동을 막지는 않지만 운영 개시 전에 모두 확인하세요. 데이터·백업 위치는 ‘자세한 설정’에서 바꿀 수 있습니다.

가상 자료로 먼저 연습하려면 실행 모드를 ‘이 PC 시험 · 외부 접속 없음’으로 바꿉니다. 시험 모드의 관리자 아이디는 admin이며 이 PC에서만 접속됩니다. 이미 운영 설정 파일을 준비한 학교는 ‘학교 운영 · 운영 설정 파일 (고급)’을 사용합니다.
### 학생·학부모 소식 서버는 필요할 때 설치합니다
업무 서버 PC에는 학생·학부모 소식 서버가 ‘미설치’로 표시됩니다. 가정통신문·학교 소식을 학생·학부모 앱으로 보낼 때 왼쪽 ‘학생·학부모 소식’에서 ‘설치하기’를 누릅니다. 학부모 휴대폰처럼 학교 밖에서 접속하려면 외부 접속 설정(5장)이 추가로 필요하며, 가능하면 업무 서버와 다른 PC에서 운영합니다.
### 자동 실행은 두 가지입니다
‘Windows 로그인 시 관리자 프로그램 자동 실행’은 관리 창을 로그인 후 여는 설정입니다. ‘관리 프로그램을 열면 이 서버도 자동 시작’은 해당 서버를 함께 켜는 별도 설정입니다. 두 항목을 구분해서 선택하세요.
Windows 사용자 로그인 전부터 서버를 켜야 하는 상시 운영은 별도의 승인된 예약 작업·서비스 구성이 필요합니다. 재부팅 시험에서 실제로 다시 연결되는지 확인하세요. 창의 X는 숨김일 수 있으므로 종료는 트레이 메뉴의 ‘서버 중지 후 프로그램 종료’를 사용합니다.
## 3. 구성원과 학교 설정을 등록하세요
### 먼저 가상 교직원 두 명을 만드세요
1. 교내 업무 서버에 관리자 로그인 후 ‘교직원·권한’에서 ‘교직원 등록’으로 이름·아이디·부서·직책을 등록합니다. 목록에서 교사를 누르면 오른쪽 패널에서 부서·직책·좌석 IP와 담당 권한(관리자·전체 공지·학사일정·특별실)을 켜고 끈 뒤 ‘변경 저장’을 누릅니다. 지정 좌석 IP는 접속 환경 정보이며 로그인 아이디가 아닙니다.
2. 기본 교직원 아이디는 이름입니다. 동명이인은 서로 다른 식별 계정을 지정하고 당사자에게 안내합니다.
3. 최초 비밀번호는 12345678입니다. 계정별 최초 활성화 코드를 안전하게 전달합니다. 첫 활성화에서 약관을 확인하고 개인 비밀번호 12~128자로 변경해야 합니다.
4. 수강신청 업무 등 관리 권한은 담당자에게만 부여합니다. 모든 교직원을 관리자로 지정하지 마세요.
### 학생·학부모와 시설
학교 소식 서버에서 학생 명부·학년·학급과 교사 연결을 등록합니다. 일괄 등록은 관리 화면의 해당 기능과 양식을 사용하고, 학생 계정·초대 정보를 학교의 안전한 전달 수단으로 배부합니다.
학부모는 본인의 임시계정으로 가입하고 설정에서 자녀의 8자리 고유번호를 입력합니다. 실제 연결 승인 방식은 학교 정책을 확인하세요. 기본은 학교 확인 후 연결이며 학교가 별도로 승인한 경우 즉시 연결할 수 있습니다.
‘특별실’에서 예약할 공간을 등록하고 ‘학급·분반’에서 소속과 담당 교사를 지정합니다. 특별실 예약은 1~7교시, 상담은 교사가 개방한 시간에 신청합니다. 학교의 실제 교시 시간을 확인하세요.
### 약관은 학교가 확정해야 합니다
‘약관·개인정보’에서 운영 학교명·문의처·처리 목적·항목·보유기간·책임자와 처리방침 열람 경로 등을 확인합니다. 03_관리자_준비양식의 파일은 미확정 초안입니다. 이름만 바꾸거나 승인 값을 true로 바꾸어 운영 승인을 대신하지 마세요.
가입·최초 활성화는 전문을 볼 수 있게 하고 필요한 동의·확인 항목을 각각 직접 체크하는 방식입니다. 학생 계정을 일괄 만들었다고 동의 이력을 임의로 만들어 넣지 않습니다.
학교가 졸업 대상과 처리 시각을 등록해야 학생의 자동 탈퇴·파기가 실행됩니다. 학부모는 마지막 재학 자녀가 졸업할 때 함께 처리합니다. 별도로 반출한 파일·백업·단말 사본의 파기도 확인해야 합니다.
## 4. 다른 PC와 휴대폰을 연결하세요
### 이 PC 시험과 실제 연결의 차이
시험 모드의 localhost는 ‘지금 사용하는 그 기기’를 뜻합니다. 서버 PC의 http://localhost:5080을 다른 교사 PC나 휴대폰에 입력해도 학교 서버로 연결되지 않습니다. 내부 시험에서 공인 운영을 시작한 것으로 판단하지 마세요.
### 학교 운영 주소 준비
1. 간편 설정을 사용하면 교내 업무 주소와 연결 확인 코드가 관리자 프로그램에 표시됩니다. 서버 PC의 IP가 바뀌지 않도록 학교 네트워크 담당자에게 고정 IP를 요청하세요.
2. 교사 PC 메신저(Windows·Mac)와 휴대폰 교사 앱은 처음 접속할 때 ‘연결 확인 코드’를 보여줍니다. 관리자 프로그램의 코드와 같을 때만 ‘예’를 누르도록 안내합니다. 이후에는 같은 서버 인증서만 신뢰하며, 코드가 다르면 접속을 거부합니다.
3. 학교가 공인 인증서·도메인을 준비해 운영 설정 파일(고급)을 사용하면 코드 확인 없이 바로 접속합니다. 주소·인증서·허용 네트워크가 맞지 않으면 먼저 이 항목을 해결합니다.
4. 승인된 학교 검색 목록을 배포합니다. 학교 등록 신청은 관리자의 학교 등록 기능에서 작성하고, 개발자 승인 후 검색에 반영됩니다. 신청 파일에는 필요한 학교 대표 연락처만 입력합니다.
### 사용자가 할 일
PC 메신저나 해당 앱에서 학교를 검색하고 학교명·지역을 확인하여 선택합니다. 아직 목록에 없으면 학교 관리자가 안내한 로컬 목록·서버 연결 방식을 사용합니다. 다른 학교 주소를 임의로 선택하지 않습니다.
자동검색은 같은 교내망에서 서버 설정과 네트워크 조건이 맞을 때 이용합니다. 무선망·다른 망에서는 발견되지 않을 수 있습니다. 관리자에게 ‘교내 업무 주소’와 ‘학교 소식 주소’를 각각 확인하세요.
> 정상 완료: 다른 PC는 교직원 메시지를 확인하고, 학생·학부모 앱은 허용된 학교 소식만 확인합니다. 내부 업무 자료가 학생·학부모 계정에서 보이면 사용을 중단하고 권한을 점검하세요.
## 5. 운영 설정과 학교 밖 접속
### 준비양식은 어디에 두나요?
03_관리자_준비양식의 원본은 그대로 남기고 학교 운영용 사본을 보호된 별도 위치에 작성합니다. 아래는 경로 예시이며 설치만으로 만들어지는 운영 완료 파일이 아닙니다.
| 파일 | 용도 |
| registration-policy.local.json | 학교가 확정한 약관·개인정보 안내 |
| deployment-review.local.json | 실제 검토 자료와 승인·유효기간 기록 |
| server-operations.local.json | 서버 역할, 저장·백업 경로, 인증서, 접속 설정 |
| cloudflared.yml | 승인된 경우의 터널 연결 설정 |
비밀번호·SMTP 인증정보·인증서 비밀키는 일반 JSON이나 공유 폴더에 쓰지 않습니다. 운영 계정과 접근 권한을 정한 뒤 안전한 입력 절차로 저장합니다. 운영 도구는 설치 폴더의 scripts에 있으며 실제 운영 설정은 담당자가 별도로 준비합니다.
### Cloudflare Tunnel을 사용할 경우
1. 학교 회선 사용과 외부 서비스 사용에 필요한 승인을 확인하고, 학교가 관리할 앱용 도메인 또는 하위 도메인을 정합니다. 기존 학교 홈페이지 도메인 전체를 바꿀 필요는 없습니다.
2. 학교 관리 계정에 2단계 인증을 설정하고 DNS와 터널을 구성합니다. 터널 연결 정보·토큰은 서버 담당자만 보관합니다.
3. 예시 apps.example.invalid를 실제 앱용 주소로 바꾸고, 터널의 목적지는 학교 소식 서버로 제한합니다. 교내 업무 서버나 관리자 기능을 함께 공개하지 않습니다.
4. 학교 소식 서버의 인증서와 호스트 검증을 유지합니다. noTLSVerify를 true로 바꿔 오류를 숨기지 마세요.
5. 교외 모바일 데이터망에서 공지·로그인·권한을 시험하고 장애·접속 로그를 확인합니다. 승인된 외부 서비스와 데이터 흐름을 약관·운영 자료에 반영합니다.
터널은 학교에서 먼저 외부로 연결하지만 익명 연결이나 보안 승인을 의미하지 않습니다. 실제 도메인·인증서·승인 자료가 없는 이번 전달본만으로 외부 접속이 완료되지는 않습니다.
## 6. 백업·업데이트·장애 대응
### 매일 확인할 것
서버 실행 상태, 디스크 여유, CPU·메모리 사용 추이, 마지막 백업 성공 시각과 장애 알림 상태를 확인합니다. 순간적인 사용량만 보고 정상이라고 판단하지 말고 동시 접속·파일 전송 시의 변화를 함께 봅니다.
운영 예시의 low-memory 자원 구성을 출발점으로 쓰되 실제 부하를 측정합니다. 이 예시는 모든 학교에서 정해진 RAM·CPU 사용률을 보장하지 않습니다. 무거운 백업과 대량 작업은 사용이 적은 시간에 수행하세요.
### 백업과 정전 대비
1. 서버 PC와 물리적으로 다른 백업 장치 또는 학교가 승인한 저장소를 준비합니다. 같은 디스크의 다른 폴더만으로 장애 대비를 완료하지 마세요.
2. DB·첨부·암호화 키·운영 설정의 복구 묶음을 관리하고 접근 권한·암호화를 확인합니다. 운영 비밀 저장은 Windows 계정에 연결될 수 있으므로 원래 운영 계정과 복구 절차를 함께 확인하세요.
3. 별도 격리 환경에서 복구하고 로그인·메시지·첨부 열람을 실제로 시험합니다. 복구 파일을 생성했다는 사실만으로 복구 성공으로 기록하지 않습니다.
4. UPS를 준비한 경우 정전 알림·정상 종료·전원 복귀 후 재가동을 시험합니다. 장애 메일은 학교가 허용한 SMTP와 수신처를 설정한 뒤 시험 발송으로 확인합니다.
### 업데이트 순서
사용자에게 점검 시간을 알림 → 백업·복구 가능 여부 확인 → 자동 시작·감시 작업 중지 → 서버 정상 중지 → 같은 경로에 새 설치본 적용 → 기존 데이터·키·설정 유지 → 서버 재시작 → 송수신·앱 연결 확인 → 감시 재개.
현재 전달본은 모두 1.0.0입니다. 정식 출시와 자동 업데이트가 활성화된 것으로 안내하지 않습니다. 제거·재설치로 문제를 해결하려고 운영 데이터나 키 폴더를 삭제하지 마세요.
### 문제가 생기면
‘상세 실행 기록’의 마지막 오류·발생 시각·해당 역할을 확인합니다. 비밀번호·인증서 비밀키·학생 정보는 공개 신고에 넣지 마세요. 서버가 뜨자마자 꺼지면 관리자 프로그램에서 시작하여 오류를 확인하고, EXE를 반복 실행하지 않습니다. 백신이나 방화벽을 전체 해제하지 말고 차단 항목·서명·필요 통신을 학교 담당자와 확인합니다.
## 7. 배포 전 시험표
### 가상 계정으로 아래 순서를 확인하세요
| 순서 | 시험 | 정상 결과 |
| 1 | 서버 설치·시작·중지·다시 시작 | 상태가 바뀌고 기존 가상 계정이 유지됨 |
| 2 | 교직원 두 명 최초 활성화·개인 비밀번호 변경 | 임시 비밀번호만으로 활성 계정 접근 불가 |
| 3 | PC 간 메시지·파일·답장 | 올바른 수신자만 내용 확인 |
| 4 | 일부 읽은 메시지 회수 | 안 읽은 수신자가 한 명 이상일 때 회수 가능 |
| 5 | 제출 요청·회수·재제출·현황 | 마감·종료 조건에 맞게 상태가 갱신됨 |
| 6 | 학생·학부모 연결과 제한 공지 | 지정 대상·담당 교사만 열람 가능 |
| 7 | 기초시간표·하루 변경·예약 | 변경한 날짜만 덮어쓰고 중복 예약 차단 |

| 9 | 백업·복구·재부팅·장애 알림 | 실제 복구·자동 시작·알림 수신을 확인 |
### 통과로 간주하면 안 되는 항목
설치 성공만으로 법규 준수·학교 심사 통과·보안 인증·스토어 심사가 완료되지는 않습니다. 시험 환경에서 확인하지 못한 항목은 미확인으로 기록하고 실제 환경에서 시험하세요.
iOS 실기기 설치, 앱 종료 상태의 푸시, Mac 일반 배포 서명·공증은 이번 전달본의 완료 항목이 아닙니다. 필수 안내의 대체 수단과 각 기기별 지원 범위를 함께 공지하세요.
### 운영 개시 전 최종 확인
학교 담당자는 운영 약관·책임자·문의처, 계정 승인과 졸업 파기, 외부 접속 검토, 역할별 열람 범위, 백업·복구와 장애 연락망을 확인합니다. 결과를 학교 내부에 보관하고 실제 명부·비밀 설정을 설치 파일과 함께 재배포하지 않습니다.
