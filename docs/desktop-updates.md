# PC 프로그램 업데이트

Windows 교무톡과 Windows 관리자 프로그램은 WinSparkle 0.9.4, Mac 교무톡은 Sparkle 2.10.1을 사용합니다. 휴대폰 앱은 대상이 아닙니다. 제품마다 다른 Ed25519 공개 키로 설치파일을 검증합니다. GitHub 정식 릴리즈의 appcast를 하루에 한 번 확인하며 사용자가 업데이트 알림에서 설치를 선택합니다. 설정에서 자동 확인을 끄거나 수동 확인할 수 있습니다.

Windows: 설정 → 프로그램 업데이트. 관리자: 왼쪽 아래 프로그램 업데이트. Mac: 내 계정 → 프로그램 업데이트. 첫 공개 릴리즈가 없으면 업데이트가 제공되지 않습니다. 네트워크 차단 시에는 공식 GitHub 릴리즈에서 직접 설치해야 합니다.

관리자 업데이트는 작성 창을 닫은 후 두 서버를 정상 중지하고 각각 DB와 첨부 전체 백업을 완료해야 진행합니다. 운영 설정의 `attachmentBackup: true`와 실제 백업 장치·권한이 필요합니다. 백업 실패나 중지 실패는 설치를 막습니다. 업데이트 후 이전에 가동 중이던 서버를 다시 시작하며, DB 자동 복원이나 강제 종료는 하지 않습니다. 최초 관리자 설치와 같은 Windows 권한 승인이 필요할 수 있습니다. 학교에서 별도 작업 스케줄러로 서버를 가동 중이면 기존 감시 작업을 전환한 후 관리자 프로그램에서 운영해야 합니다.

세 저장소의 GitHub Actions `UPDATER_ED25519_SEED` 비밀값으로 릴리즈 설치파일을 서명합니다. 공개 키는 `config/update-publisher.json`에 포함되며 비밀 키를 Git에 넣으면 안 됩니다. 개발 PC의 Windows DPAPI 보호 사본은 현재 Windows 계정에 묶입니다. 다른 PC로 옮기거나 계정을 초기화하기 전에 담당자가 별도 암호화 백업을 준비해야 합니다. 키 교체는 기존 앱이 신뢰하는 키와의 이행 계획이 필요합니다.

현재 모든 프로그램 버전은 1.0.0입니다. 공개 릴리즈는 만들지 않았습니다. 정식 출시를 결정한 후 저장소의 태그·Directory.Build.props·updates.json 버전을 맞춰 릴리즈를 공개하면 검증 작업이 설치파일과 서명 피드를 올립니다. CI 실패나 서명 키 불일치는 업로드를 중단합니다. 원본 설치파일의 Authenticode 및 Mac Developer ID·공증은 업데이트 서명과 별개이며 실제 인증서 준비가 필요합니다. Mac은 서명·공증 준비 전 출시 예정으로 유지합니다.
